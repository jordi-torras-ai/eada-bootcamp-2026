Overview

Observations

About the dataset

01

This project analyzes the “Credit Risk Dataset” shared on Kaggle. The data contains borrower characteristics, requested loan details, credit-history indicators, and a binary outcome.

The target is loan_status: 0 indicates no recorded default and 1 indicates a recorded default. The observed default share is in the source file.

This is a historical educational dataset with limited information about collection time, sampling, and original population. It should not be treated as a current or representative sample of borrowers.

Use the report to learn from a classification workflow. Its performance estimates apply only to a held-out subset of this dataset.

Data quality considerations

Missingness and duplicates

Exact duplicate rows were removed before the train/test split so identical records could not appear in both partitions. Records with no target label are excluded from model fitting.

Predictor timing and scope

Interest rate and loan grade can reflect a lender’s prior underwriting assessment. Their timing relative to the outcome is not documented clearly enough to rule out proxy or timing leakage. This model should be interpreted as a demonstration of association, not a deployable decision system.

The dataset is historical and its collection period and population are not sufficiently documented for claims about current borrowers.

Interpretation and conclusion

Patterns to notice

    Analytical conclusion

    The dataset has a meaningful class imbalance and incomplete values in two predictors. Median imputation and class weighting make model fitting possible, but do not remove uncertainty about the data-generating process. Extreme observations in age, employment length, and income warrant a sensitivity analysis before drawing strong conclusions.

    The most useful next analytical check is to compare results with and without underwriting fields such as grade and interest rate, then discuss whether the intended prediction time would make those variables available.

    More detail
    What were the training and evaluation steps?

    Exact duplicate rows and records missing the outcome were removed. The remaining labeled data was split into 75% training and 25% test records, preserving the class proportion (random seed 42). Missing numeric values were filled with training medians; missing categories with the training mode. Categories were one-hot encoded and numeric values standardized in the shared preprocessing pipeline. Each algorithm was fit on the training partition and evaluated once on the same held-out test partition.

    The three algorithms were logistic regression (linear relationship in log-odds; balanced class weighting), random forest (an ensemble of decision trees; balanced class weighting), and gradient boosting (sequential decision trees; no class weights in this configuration). The comparison is one reproducible holdout experiment, not cross-validation.

    What do the other metrics mean?

    Precision: among cases the model labeled as default, how many were recorded defaults. Recall: among recorded defaults, how many the model found. F1: a combined measure of precision and recall. Accuracy: share of all labels predicted correctly. ROC AUC measures ranking quality across thresholds.

    Limitations and conclusion

    • This is one random holdout, with no cross-validation, external validation, or test on newer borrowers.
    • Loan grade and interest rate may encode prior underwriting judgments. Their timing is unclear, so possible proxy or timing leakage remains.
    • The 50% threshold is illustrative. No threshold optimization, probability calibration, subgroup fairness analysis, or causal analysis was performed.
    • The dataset’s historical context and representativeness are limited. These findings cannot establish individual behavior or support real lending decisions.

    The Risk estimate page uses logistic regression refit on all labeled, deduplicated rows for browser inference. It is distinct from the highest-ranked holdout model.
